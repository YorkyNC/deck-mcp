# Бриф: MCP-сервер для генерации презентаций

## 1. Суть в одном предложении
MCP-сервер, который превращает тему или сырой контент в готовую красивую
презентацию (HTML-ссылка + редактируемый PPTX) за один-два промпта, на базе
гибридной дизайн-системы «шаблон-пак + AI-подстройка». Язык — русский.
Модель продажи — сервис.

## 2. Пользователи и сценарий
- **Оператор сервиса (ты):** принимаешь запросы клиентов, прогоняешь через MCP, отдаёшь результат.
- **Клиент:** предприниматель / отдел продаж, которому нужен питч, КП или доклад, но нет дизайнера и времени.
- **Два входа:**
  - *Тема одним промптом:* «Питч для SaaS по аналитике, 10 слайдов» → AI сам придумывает структуру и текст.
  - *Промпт + контент:* клиент кидает текст/цифры/документ → AI структурирует и оформляет (основной надёжный режим для реальных КП).

## 3. Ключевое архитектурное решение
Сервер **не переизобретает LLM**. Контент, структуру и тексты пишет Claude
(клиент MCP). Сервер отвечает за то, что промпт в одиночку не даёт:

| Делает Claude (модель)                | Делает MCP-сервер (детерминированно) |
|---------------------------------------|--------------------------------------|
| Придумать структуру, тексты, заголовки| Хранить дизайн-паки (темы, лейауты)  |
| Заполнить слайд-схему (JSON)          | Рендер JSON → reveal.js HTML         |
| Выбрать подходящий шаблон             | Рендер JSON → PPTX                   |
| Подобрать акцентный цвет/тон          | Деплой HTML, выдача ссылки           |

Тонкий сервер, вся генерация — на стороне модели.

## 4. Дизайн-система (гибрид)
- **База:** 3–5 фиксированных стиль-паков (`minimal`, `glass`, `corporate`, `dark-pitch`, `gov`).
  Каждый пак = набор лейаутов (title, bullets, two-column, big-number, quote, closing) + токены (шрифт, цвета, отступы).
- **AI-подстройка:** модель меняет акцент, плотность контента, подбирает лейаут под слайд — в рамках пака, поэтому результат предсказуемо аккуратный.
- Один слайд-schema (JSON) рендерится и в HTML, и в PPTX — единый источник правды.

## 5. Поверхность MCP (MVP-инструменты)
```
list_templates()                       → галерея стиль-паков
create_deck(deck)                      → валидирует slide-JSON, сохраняет, возвращает deckId
render_html(deckId)                    → reveal.js HTML (+ деплой), возвращает ссылку/путь
render_pptx(deckId)                    → .pptx файл                      [позже]
refine_slide(deckId, slideId, instr)   → правка одного слайда            [позже]
```
Поток «один промпт»: Claude заполняет deck-JSON → `create_deck` → `render_html` → ссылка.

## 6. Технологии
- **Сервер:** Node/TypeScript (MCP SDK). Slice — plain JS ESM, без билд-шага.
- **HTML:** reveal.js (CDN) + свои CSS-темы, самодостаточный файл, деплой Vercel.
- **PPTX:** `pptxgenjs` (PPTX-дизайн беднее HTML — осознанный компромисс, HTML остаётся витриной).
- **Хранилище дек:** JSON на диске (`decks/`), БД потом при необходимости.

## 7. MVP vs позже
- **MVP (этот срез):** 1 стиль-пак, вход через deck-JSON, HTML + деплой.
- **Позже:** второй вход-режим отшлифовать, PPTX, PDF, Google Slides, графики из цифр, картинки, брендинг клиента, биллинг.

## 8. Открытые вопросы (не блокируют старт)
1. Деплой HTML — под своим доменом (`deck.домен.kz/xxx`) или отдельные Vercel-ссылки?
2. Картинки/иконки — готовые наборы (Lucide/Unsplash) или генерация (fal.ai)? MVP: наборы.
3. Монетизация: за деку / подписка / white-label? Определит, нужен ли биллинг в MCP.
